# FarmDESIGN 本地工作台

本模块直接调用作者发布的 FarmDESIGN **4.21.5.0** 计算程序集及其原版差分进化优化器，软件身份固定为该版本。作者 DLL 保持原字节；网站、适配器、案例、原版程序和原始资料分别保存。

## 启动与数据位置

首次配置或需要重新核验作者资料时，在仓库根目录执行：

```powershell
python tools/prepare-farmdesign.py
node tools/build.mjs
python -X utf8 tools/serve.py --directory _site --port 4174
```

打开 `http://127.0.0.1:4174/#farmdesign`。已有本地开发目录的“启动本地Farm.cmd / .ps1”仍会构建网站并启动服务。配置工具也接受 `--source <原作者归档目录>`、`--runtime <独立运行目录>`；服务接受 `--farmdesign-runtime` 或环境变量 `FARMDESIGN_RUNTIME`。

程序使用 Windows 已有的 32 位 .NET Framework / PowerShell 以及原作者的 Access 数据库。准备工具读取原数据库，复制到独立运行目录；每个计算进程再使用自己的临时数据库副本。原始包不被回写。网页和计算服务都绑定本机，不需要互联网，也不发送模型输入到外部网站。

**原版计算需要本机服务保持运行。** 关闭服务后，已有地图和 A/B 浏览器离线功能继续保留；FarmDESIGN 原生计算无法仅靠浏览器缓存完成。GitHub Pages 静态托管不能执行这些 Windows 程序，未来在线发布需要部署相应计算服务。当前没有推送或部署。

另提供 Windows 便携构建：整包包含网页、官方嵌入式 Python、原版引擎和数据库，双击包内“启动Farm.cmd”运行，不需要目标电脑安装 Python、Node 或 Office。便携版将应用持久存档同步写入包内 `UserData/workspace.json`，关闭服务后可随目录复制。旧网址的浏览器存档需先导出项目，再在便携版导入；复制代码不会自动带走旧浏览器数据。具体电脑条件、启动检查和恢复方法见便携包根目录“使用说明.md”。

## 完整工作流程

1. 选择作者案例，或从当前模板“新建项目”。新项目保留模板的来源身份，需要以自己的资料替换参数。
2. 在“活动与参数”编辑农场、土壤、经济、轮作面积、作物、产品用途、畜群、畜产品、粪肥、肥料与农药、家庭、机械建筑以及营养参考资料。保留原版字段与数据类型，可增加或删除记录；关联存在时先修改关联再删除。
3. “重新核算”调用原版 FarmSimulation。检查完整核算、指标、单位、缺失状态和启用约束。
4. 在“多目标优化”设置原版可调属性、上下界、精确约束、目标方向和附加指标约束。原案例的已启用约束继续保留。开始后按原版代数推进，可以停止搜索。
5. 选择非支配方案，重新调用原模型计算；可应用为当前设计，再保存完整方案。保存包含输入、输出、原版身份和 SHA-256 内容摘要。比较页逐项对照两个保存方案。
6. 导出本工作台 JSON、原版 XML、指标 CSV 或完整原生项目 ZIP。导入运行记录先检查摘要，再重新核算，不把文件里的旧输出直接当作新计算。

全部 24 张核心参数表可编辑。原始数据库的笔记、照片引用和版本表作为辅助资料保留；不是新的经营决策变量。空间地图与既有 A/B 路线继续使用自己的输入合同和来源记录。

## 全局语言

顶部“中文 / EN / 中/EN”控制整个工作台。24 张核心表的 235 个不同输入字段、原版结果路径与指标、优化变量、单位、状态提示和已打开的说明窗口使用同一显示模式；B 路线、完整离线页和便携保存状态同步使用该偏好。已打开的同源页面之间会同步切换，刷新或重启后保留选择。

中文模式显示中文标签，英文模式显示英文标签，中英同显模式配对显示两种语言，不再把相同英文重复两遍。原版字段与结果路径可通过“显示原版代码”查看；JSON/XML、编号、产品或项目名称、输入值和原始记录保持原样。导出的界面 CSV 使用所选语言的可读标题，并保留原版代码以供追溯。语言切换不转换单位数值，也不改写计算数据或已保存方案。

## 核算范围

原版模型的土地与轮作、产品多用途和净贸易、两饲喂期供需、饲料自给、畜产品、粪肥处理及损失、有机质、N/P/K/C、劳动、水、农药、机械建筑与经营经济、温室气体、生物能、家庭预算、营养及食物多样性、流网络均可由原版代码核算。界面提供 20 组原生输出，以及在当前农场上实际解析成功的原生目标目录。目录由原版指针解析，不能把任意页面数字当作优化目标。

模型使用年度静态、稳态、目标产量口径；它不会自动变成逐日作物生长、土壤水分或投入响应模型。原作者的越南案例是软件案例，不是海南实测参数。原始案例许多排放和生物能参数为零，结果应结合输入解释，不作为完整排放清单或生产建议。

## 三项重要输入合同

- 作物产品用途以 kg 干物质计，畜产品用途以 kg 鲜重计；N/P/K 为元素量及干物质百分比，不直接接受 P₂O₅/K₂O 替代。劳动使用小时，货币保留项目定义。
- 温室气体总量 `TotalEmissionCO2eq` 为 **Mg（吨）CO₂eq**；子模块 `CO2eq` 为 kg。水的 `WaterBalance` 为供需偏差百分比，不能标成 m³。饲料能量在默认 VEM 模式下的汇总输出为 kVEM；相应自给率和营养自给率按原版百分比显示。
- 缺少输入或分母时，原版可能返回 NaN/Infinity。适配器保留“未定义”状态，不替换成有效的零。人工构造的机制测试只证明软件关系，不能证明校准或可行管理方案。

## NFD 营养功能多样性

“来源与模型”可装入三份原版文本附件。没有附件时明确显示未配置，原版默认零不被解释为实际 NFD 分数。

- Dendrogram：制表符分隔。首行是分枝长度；其后每行为一个物种对应的 0/1 分枝归属，列数一致，分枝总长度为正。
- Mapping：无表头，两列为产品键和从零开始的物种行。产品键为 `100000 + PrdID` 或 `200000 + AprID`。
- Products：每行一个物种／产品名称，行数与树中的物种数一致。

文件以原版所需名称写入本进程的 Input 副本：`<农场名称空格替换为下划线>.FD.Dendrogram.txt / Mapping.txt / Products.txt`。真实营养性状树仍需有来源的营养资料和前处理方法；软件不会生成虚假的实测性状。

## 网络模式与资源兼容

提供原版 None、Simple、Complex 模式。原包的 Simple 资源文件只有 35 个流索引，而该 DLL 的养分输出多了 4 个效率比率。适配器在运行副本尾部添加四个原生 `-1` 忽略索引，保留前 35 项物质流；不把比率写入物质流矩阵，也不修改 DLL 或原资料。调整前后资源哈希记录在运行时身份文件中。

宿主只在自己的进程中修正原程序的 StartupPath，使图形和网络资源从复制的 Bin 读取，不写入 Windows 目录。两种实际计算模式均以非零流量场景核验；“未启用网络”与“计算得到零循环”分别说明。

## 优化与解释

使用原版 Rand1Bin / ParetoRank、原版种群初始化、变异、交叉和选择。界面默认使用较小交互预算；范围支持 8–600 个解、1–10000 代。原案例完整参数和原始 600 / 10000 设置保留在项目配置中，可按需要调整。

原版未公开可设置的随机种子，界面不声称相同输入得到完全相同随机前沿。进度报告原生代数；不伪造精确评估次数。原返回数组有 2N 行，后 N 行是工作区，适配器只读取前 N 行。最终逐个候选重新计算，并检查原版决策、目标和约束，再按实际目标筛非支配方案。没有找到方案不构成全局不可行证明，有限次启发式搜索不构成收敛或全局最优证明。

## 原生交换和保存

JSON 保留全部表、参考资料、工作台设置、来源和可选 NFD 文本。原版 XML 通过作者的 XmlSerializer 和导出器交换；原版 XML 本身不包含全部 DRI/DRF/DEP 与旧字段，因此导入明确记录所用作者参考库。完整项目 ZIP 另含当前编辑后的 FarmDB.mdb、de.mdb、原版 XML、JSON、来源身份以及全部 20 组模块 CSV；NFD 已配置时附带其三份文本。重复 XML 导出使用独立位置，避免原版文件追加行为产生多个 XML 文档拼接。

原始研究材料和原版数据库继续保留在原位置；工作台存档仅写入本地浏览器或由用户下载。分享文件前按实际内容检查资料范围。页面内容摘要证明保存内容的完整性，不证明数据来源真实或科学模型适用。
