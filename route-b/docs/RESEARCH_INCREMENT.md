# 海南方案B研究设计与下一计算补丁

## 研究主张和先后关系

建议先将B定位为“海南分层经营系统的机制研究”，保留与PhD1共同案例，再把有证据的跨主体共享资源放在上层。只有抽样覆盖、权重与区域资源边界经过检验，才升级为省域总量推断。省、县只是背景与汇总层；经营权、真实水源、物流接收地和环境受体才定义决策及相互影响的边界。

本次新组合是“分层选样 → 有日期的经营活动账 → 局部可行完整菜单 → 共享资源检查 → 同信息配对策略检验”。其各组成有文献依据，组合在海南是否有效尚待检验。文献里的参数、原作者算法实现和跨案例改善率均不自动移植。

## 目标一 时空差异与适应框架

原目标见 `PROPOSAL_ALIGNMENT.md` 第1项。

A以共享案例经营单元及地块的差异/变化为观察对象。B增加环境×生产活动组合×资源可达性的分层覆盖；最小记录仍为经营者ID—生产单元ID—活动ID—实际日期，县年统计不能当经营者逐季观测。

- 研究单元：真实经营者、其可决策土地/设施、水源连接；环境层和行政代码带版本。先用有解释力的少数分层变量，不为了覆盖每县强造代表户
- 时间：区域年序列用于趋势；活动按播种/收获季；劳动与水按实际作业事件或关键周/月。资源约束步长须能区分瓶颈，不能一律把年值等分为12月
- 观测：实际地块/设施及权限、土壤/灌溉条件、播收日期、每次投入与作业、产出和价格日期、外部事件与何时获知、数据缺失原因。统计年鉴和地图另保留空间支持与年度
- 外部参数：分层环境产品的分辨率和分类误差、气象历史/预报版本、土壤与适宜性模型适用范围。198行植物目录可提候选问题，不能当198户样本或带位置的海南观测
- 模型接口：事件表输出带单位、总量与时间分配规则的资源向量；知识目录与调查表分开。新增代码只接受完整声明的合成事件账，实际观测通道以后另审
- 变量与约束：此阶段主要决定分层与时间粒度，不优化土地。比较同总量、同候选下聚合/分层及年度/逐期可行集；先检查数据支持而非直接最大化指标
- 验证：在独立经营者、未拟合地域/年份上验证资源/产出预测；地图精度单独核，不能由模型拟合证明。若细化时间或分层并未稳定改变独立误差与可行性，承认复杂化收益有限

依据：Xu2024 PDF4 Eqs1–2区分加权平均与总量、调查跨地块与一年边界；Xu数据论文PDF6–10/12把村、户、作物层级和分层过程分开；FarmSTEPS PDF5 §§2.1.3–2.1.5给时间起点、窗口、历史和跨期归属；Groot2017 PDF8–9的参与制图和季节历帮助交叉核实，不是统计代表性保证。

## 目标二 跨活动模型开发与检验

原目标见第2项。A将PhD1作物候选与案例农场其他活动整合；B先按可比层生成有限个完整经营菜单，再通过真实资源节点连接。上层不能任意切碎家庭劳动、固定资产或既定种养结构，假设单位整数份数也不等于真实覆盖权重。

- 研究单元：经营单元中的活动—产品—库存—转移；跨主体只连有权限且有供需记录的边。种植为起点，畜牧/水产/农林只有具备对应观测和参数才接入
- 时间：作物季与操作事件；有动物时需饲喂、产出、排泄及库存时间；水产需养殖周期、投饵、换水/排水与收获。不能仅加一个“养殖面积×平均收益”就声称整合
- 观测：作物投入产出/损耗/用途；如纳入畜牧，需动物类群和数量、饲料来源与去向、产品、粪肥链；如纳入水产，需养殖设施、饲料、水和排放记录。缺项保留unknown并关相应推断门
- 外部参数：产量/管理响应、产品干鲜重和N/P成分、动物营养需要、粪污各环节损失及利用率、运输储存费用、环境响应。逐项附来源/适用系统/误差，不套荷兰VEM/DVE、华北排放因子或未取得补充的参数
- 模型接口：PhD1提供候选ID、土地条件、日历/历史规则、管理版本、产量及资源系数、误差；PhD2返回水/劳动/现金瓶颈和不可实施时窗。物料接口用来源—去向—日期—kg元素N/P，固定成分物料须按同一份额拆分
- 决策变量：经营者可选作物/序列菜单、被允许的活动规模、购买/出售/转移量。已有多年生作物、设施、历史与承诺锁定；土地、逐期水/劳动、现金、饲料、库存、接收地N/P双容量与物流均需明示
- 验证：手算与独立代码先验守恒；再对独立活动、全场记录验证产出/需求。所有源输出=去向输入+损失+库存变化；内部回流在区域边界消去，不能当新增外部投入或两次收益。单一N/P分份函数通过不等于整场平衡通过

可采用的计算骨架（本方案表达）：对每种物料k、节点u、期t，S(u,k,t+1)=S(u,k,t)+外部输入+产生+转入−消耗−转出−损失。每项有相同质量与时间边界。损失因子估算和余额未知残差须分列，不能把未解释残差直接贴成实测排放。

依据：Groot2012 PDF3 Fig1/§2.2.2–2.2.3将产品流、饲料需求和两期饲料分开；PDF5 Eqs7–17为粪肥关系，不能跨案例抄参数。Qu2025 PDF4 §2.2让FarmDESIGN输出物料到FarmM3，再返回可施用物料，正是当前B尚缺的反馈。FarmSTEPS PDF17明确尚未纳入牲畜、副产品配置和景观修改，所以跨活动是本方案扩展，不是假称原模型已有。

## 目标三 资源配置与适应改进

原目标见第3项。A在案例经营权内优化养分、水、劳动；B增加可行经营菜单之间的共享资源竞争。当前B完整整数菜单枚举可作为软件基准；正式区域算法等数据规模和决策权明确后再选，不预设全省逐块穷举或唯一算法。

- 单元：经营者选择自己的菜单；协作机构只分配获授权的共享设施/水/物流服务。区域层是约束与协调，不假设存在全省统一经营者
- 时间：t0发布初始计划；之后观测在availableAt时进入；已发生/承诺活动不可倒改；下一可调整窗口才允许改动作
- 数据/参数：初始状态、同一外生天气/价格/供给轨迹、各事件被知道的时间、允许动作、调整成本和等待时间、恢复成本、库存与现金；无概率依据只做命名情景，不报精确风险分位数
- 变量与约束：x(h,m)为经营者h选择菜单m的0/1变量，Σm x=1；对有真实交换性证据的组才可用整数计数。共享源s在t期满足Σh,m connected(h,s)·water(h,m,t)·x(h,m)≤capacity(s,t)。养分容量与劳动/资金同样明确边界。食品底线分品类，不能用蔬菜量补粮食缺口
- 评价：五领域分别列指标与缺口，不强制五个优化目标；现代码毛利↑、外部N↓、水↓只是合成示例，P是硬情景上限。粮食产量不是完整粮食安全；毛利不是家庭福利；Q观点不是权重；N/P输入减收获不是损失模型
- 验证：有限小例完整枚举检查搜索正确性；真实数据留出检验；参与者确认可实施/拒绝条件；前瞻追踪实施与结果。算法找到非支配解不等于经验或因果验证

固定/可调配对回放后续协议（本次未实现）：两策略共用初始信息、菜单/动作集、预算和外生轨迹；固定策略t0定稿，可调策略仅在相同信息逐步到达后更改允许动作并支付同口径费用。每个决策保存可见数据版本；把未来轨迹改掉但保持过去一致时，当期及以前动作必须不变。完美预知仅可单列为上界诊断，不参与“适应收益”命名。保留不可行与未执行计划，不靠自动放松约束制造成功。

科学问题：在不额外给资源和新候选的条件下，允许适时调整是否减少不可行事件/损失，是否值得其成本？若收益来自额外候选、较高投入或事后信息，不能归因于适应性。出处：Landscape2007 PDF7/9约束与跨尺度权衡；Landscape2018 PDF4 Fig3解码—评价—约束的分离；Verdouw2021 PDF7–10是观测到控制的概念接口，不是B实时孪生已验证；Toorop2023的反脆弱概念不是本回放已经证明的结果。

## 日期事件样板的边界与最小验收

样板只做劳动h和水m³的总量分配，不把每公顷值自动乘面积，不转换养分单位，不处理产量、毛利或环境损失。事件已是一个菜单/经营者/生产单元的总量；半开日期区间[start,end)，日粒度，不跨时区转换。点事件按日期归期；区间事件仅在明确声明“均匀持续”假设时按重叠天数分配。农忙高峰应使用实际事件，不能默认平摊。空白日只有在完整事件账声明下才是未发生；一个资源整列缺失拒绝，已知零须有明确零事件。

输出保存每项原值、分配值、来源、参数版和归期依据。两期可跨年、支持闰日；周期必须有序连续且无重叠，超出窗口的事件拒绝而非截掉。只更新菜单资源数组，其余指标保持原样，再由B重跑约束。现原型并不验证作物时窗、轮作返回期或已承诺作物，因此不能称时间排程器。

已跑：26项新单元测试（缺失/null/NaN/负数、错误单位、日期、层级、重复、稀疏、区间越界、归期规则、显式零、闰年、1000个幅值守恒等）；30项原引擎测试；一次端到端合成对照。日期化原例仍9组合/年度8/逐期5；同总量140h改为首期后年度8/逐期3。这个结论只说明约束对时间分配敏感。

负责人整合后尚需验收：新输入与导出版本绑定；导入重算不信存储结果；并发导入/重置/草稿修改不回写过期结果；错误提示可定位事件；可导出审计；旧快照仍可读；中英文与手机/桌面真实浏览器；全套原回归；构建哈希更新。本次没有修改UI，也没有对这些整合项报通过。

## 导师讨论需要定的四件事

1. B主要终点是分层经营系统的机制证据，还是带代表性权重的省域估计？推荐先前者，后者设证据关口，不把覆盖范围默认为科学边界
2. 哪个共享案例承接PhD1候选与反馈？最先取得哪个真实劳动/水瓶颈，支持何种时间粒度？不预先指定样本量
3. 首个非作物活动选哪一个，以及是否有完整记录可支撑？没有就保留接口与缺口，不为了“综合农业”造数
4. 谁拥有调整权、允许何种动作、何时承诺和调整成本如何观测？这些决定固定/可调检验，不能由界面默认代替
